# Demo 样例说明

> 两个固定课例样例（三年级数学"分数的初步认识"）的构成、植入缺陷与预期行为对照。
> 证据类型：本目录全部输入材料属于 `design`（团队制作的演示设计材料）。

## 1. 样例清单

| 样例 | 输入 | 关键差异 | 预期流程结果 |
| --- | --- | --- | --- |
| `normal-case` | curriculum-source.md + lesson-draft.md + learner-summary.json + rule-pack.json | 完整输入 | Evidence Packet = `READY` → Design 产出 revision.md → Audit 产出 audit_report.json → 导师批准 |
| `missing-evidence-case` | lesson-draft.md + learner-summary.json + rule-pack.json | **缺少 curriculum-source.md（关键课标证据）** | Evidence Packet = `BLOCKED` + 缺失项清单 → Manager 停止，不调用 Design Agent → 向导师展示补证要求 |

## 2. 初稿植入的三个可审计缺陷

初稿 `lesson-draft.md`（两个样例内容相同）故意保留以下问题，供 Evidence→Design→Audit 流程发现：

1. **目标 3 无评价任务**：教学目标 3"在小组合作交流中发展数感和合作意识"在评价任务表中为空（触发 R-001），且未映射任何课标条目（触发 R-004）。
2. **未处理高频误解**：学情摘要 M-01"分母越大分数越大"（17/42 观测频率，为最高频错误模式）在教学过程中没有显式处理环节——环节 3 只做同分母比较 1/4 与 3/4，未触及 1/2 与 1/8 这类分子为 1 的比较误解（触发 R-003）。
3. **设计理由无证据引用**：理由 2"三年级学生注意力持续时间有限"没有任何 evidence_id 引用（触发 R-002）。学情摘要中虽有对应合成观察记录，但初稿未引用，需由 Design Agent 补引。

通过项（证明审计不是"全部报错"）：各环节均标注时长且总计 40 分钟（R-005 通过）；目标 1、2 已映射 CUR-02 并有对应评价任务。

## 3. 合成与合规标记

- `learner-summary.json` 顶层字段 `"synthetic": true`，并在 `data_notice` 中声明不含真实学生个人信息；所有统计为演示虚构。
- `lesson-draft.md` 文首与文末标注 synthetic，为团队原创。
- `curriculum-source.md` 只含短引用与官方来源链接（教育部官网，教材〔2022〕2 号），不分发课标全文；CUR-03 明确标注为转述。

## 4. 输出物约定

| 文件 | 生产者 | 说明 |
| --- | --- | --- |
| `evidence_packet.json` | Evidence Agent | 状态 `READY` / `BLOCKED`，证据条目含 evidence_id |
| `revision.md` | Design Agent | 修改建议，关键建议引用 evidence_id |
| `audit_report.json` | Audit Agent | 按 rule_id 逐条给出 PASS/WARN/FAIL/NA |
| `review_decision.md` | 人类导师 | 批准/驳回决定与理由 |

expected-output 目录中的上述文件为 `fixture replay`（预先设计的期望输出），真实运行产物（`live`）将存放在 `evidence/` 并登记入 `docs/运行证据索引.md`。
