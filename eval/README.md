# 首批评测集骨架（MVP-001）

> 状态：2026-08-16 建立结构；样例待填充（来源必须为公开 / 授权 / 明确合成）。
> 用途：验证规则命中率、证据引用正确率、误报/漏报与人工审批门，作为 `docs/阶段决策-导师可试用MVP.md` 两周验收的数据来源。
> 边界：评测集是**验证材料**，不是 live 产物；样例标注预期结果不冒充真实运行。

## 1. P0 规则（来自 `demo/normal-case/input/rule-pack.json`）

| rule_id | 名称 | 判定要点 |
| --- | --- | --- |
| R-001 | 目标—评价一致性 | 每条目标至少一个非空评价任务 |
| R-002 | 关键理由证据化 | 每条关键设计理由引用证据包内 `evidence_id` |
| R-003 | 学情误解响应 | 针对最高频误解的显式标记 `【响应学情 {id}；证据 {ev}】`（确定性检查） |
| R-004 | 课标映射 | 每条目标映射到可验证的 CUR 课标条目 |
| R-005 | 课时结构完整 | 各环节标时长，总时长 ≤ `max_total_minutes`（40） |

## 4. 标注 schema（≥1 名导师标注）

每条样例由导师（人工）标注：

```json
{
  "sample_id": "S-01",
  "导师风险标注": "关键风险描述",
  "建议决定": "直接接受 | 修改后采用 | 拒绝",
  "规则误报": "系统标 FAIL 但导师认为合理(可空)",
  "规则漏报": "系统标 PASS 但导师认为有问题(可空)",
  "证据引用正确率": "正确/总数(样例层面可统计)",
  "备注": ""
}
```

## 5. 两周验收指标来源

| 指标 | 数据来源 |
| --- | --- |
| 证据引用正确率 | 评测集标注 + 运行产物证据引用校验 |
| 规则误报/漏报 | 评测集标注 vs 系统判定 |
| 建议接受/修改/拒绝比例 | 导师在试运行中的决定统计 |
| 导师单次任务耗时与卡点 | 访谈记录（`docs/mvp-001-导师访谈引导.md`） |
| 未经人工审批进入发布次数 | 运行门禁日志（硬指标，必须为 0） |
