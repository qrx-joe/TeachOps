- [ ] 终端执行 `uv run python scripts/replay_fixture.py` 的完整结果，画面必须同时出现 `evidence_type: fixture replay` 与 `live_agentteams_run: false`。
- [ ] `demo/normal-case/fixture-replay-output/evidence_packet.json`，确认 `status=READY`。
- [ ] `demo/normal-case/fixture-replay-output/revision.md`，确认关键建议引用 `EV-*`。
- [ ] `demo/normal-case/fixture-replay-output/audit_report.json`，确认 `report_id=AR-normal-001` 且保留人工决定边界。
- [ ] `demo/normal-case/fixture-replay-output/review_decision.md`，确认绑定 `AR-normal-001` 且页首标记 `fixture replay`。
- [ ] 如需校验留存副本，执行 `Get-FileHash demo/normal-case/fixture-replay-output/* -Algorithm SHA256`，把结果与四个文件一起保存。

建议截图文件名：`fixture-replay-01-command.png`、`fixture-replay-02-four-artifacts.png`。它们不能放入 `evidence/live-*`。

## B. 后续 AgentTeams 跑通后才留存：live

- [ ] Docker 与 AgentTeams 版本/健康状态。
- [ ] Element Web 本地地址与登录成功画面。
- [ ] Team Room 中 Manager、Evidence、Design、Audit 四个角色列表。
- [ ] Manager 分派 Evidence 的消息与 READY 产物引用。
- [ ] Design 返回 `revision.md` 的消息与 Evidence ID 引用。
- [ ] Audit 返回 `audit_report.json` 的消息与 WARN/PASS 结果。
- [ ] 用户批准或驳回的原始消息，以及对应 `review_decision.md`。
- [ ] 四个 live 产物的生成时间、文件哈希与运行批次说明。

live 文件统一命名为 `evidence/live-XX-描述.{png,json,md}`，并登记到 `docs/运行证据索引.md`。
