# 项目定位与命名（已冻结）

> 冻结日期：2026-08-14（步骤 1）
> 变更规则：初赛提交前不再修改。作品简介、PPT、README、仓库名中的名称与定位以此文件为准。

## 1. 作品名称

- **全称**：研序 TeachOps：多 Agent 教学设计预审与质量治理系统
- **简称**（PPT 页眉、演示、沟通用语）：TeachOps
- 拼音品牌"研序"仅出现在全称中，避免与英文简称并列造成识别负担。

## 2. 一句话定位

> TeachOps 让 Evidence、Design 和 Audit Agent 围绕同一份教学设计协作，导师可以核对依据、处理风险并确认最终结果。

## 3. 100 字问题描述

> 师范院校和教师培训中，教学设计初稿常缺课标依据、目标与评价脱节、学情回应不足，导师人工预审重复且口径不一。TeachOps 用多 Agent 流水线把预审拆成取证、修订、稽核三步，每条建议可回溯证据，缺关键证据即阻断流程。

## 4. 范围冻结确认

| 项 | 冻结结论 |
| --- | --- |
| 首要用户 | 仅"师范院校或教师培训导师"（含助教） |
| 主场景 | 仅"教学设计预审" |
| 主课例 | 仅"小学三年级数学：分数的初步认识" |
| Agent 数 | 4 个（Manager、Evidence、Design、Audit），人类导师是审批者不是第 5 个 Agent |
| Skill 数 | 3 个（build-evidence-packet、revise-lesson-with-evidence、audit-lesson-alignment） |
| 演示分支 | 正常流程 + 缺证据异常流程，共 2 条 |
