# 阶段决策：导师可试用 MVP（DEC-001 · 方向 B）

> 决策人：项目负责人（2026-08-16）
> 决策背景：初赛材料已齐备（live 证据 L1-L5、PPT/PDF、简介），但未做任何真实用户验证。经权衡选择**导师可试用 MVP**，而非比赛收尾。
> 依据：`docs/下一步实施与修复计划.md` DEC-001；已完成的 live 证据与 Skill Contract 直接作为 MVP 起点。

## 一、目标用户

师范院校教学法教师 / 教师培训机构导师，**3–5 名**。画像：经常承担教学设计预审、愿意保留"依据-决定"记录、每周至少 1 次预审任务。

## 二、核心场景

导师提交教学设计初稿 + 配套材料 → TeachOps 完成 **Evidence → 候选修订 → Audit → 导师人工决定（批准/附条件/驳回/补证）→ 导出审核包**。导师能逐条核对每条建议的证据依据并留下决定记录。

## 三、首期范围

任务输入（课标来源 / 初稿 / 学情 / 规则包）、Evidence、候选修订、Audit、人工决定、导出审核包。沿用现有固定课例与三个 Skill Contract，**不新建产品功能**。

## 四、明确不做

- 复杂 LMS 集成（LTI / OneRoster）
- 自动规则学习
- 大规模多租户、区域部署
- Web 工作台重写、数据库 / RAG 引入
- 更多课例扩展

## 五、两周验收（可验证指标）

1. **3–5 名导师每人至少完成 1 次完整预审**并给出结构化反馈。
2. 证据引用正确率 ≥ 阈值（初始参考 ≥80%，最终以访谈基线确定）。
3. 记录规则命中的**误报与漏报**（≥1 名导师标注关键风险与建议接受/修改/拒绝结果）。
4. 统计建议**直接接受 / 修改后采用 / 拒绝**的比例。
5. 记录导师完成一次任务的**耗时与主要卡点**。
6. **未经人工审批进入正式发布的次数必须为 0**（硬指标）。

## 六、终止条件

- 2 周内无法约到 **≥3 名导师**参与 → 转向方向 A（比赛收尾 / 冻结）。
- ≥3 名导师明确表示预审场景不成立或不愿采用 → 停止 MVP，记录假设失效。
- 评测集证据引用正确率过低或关键规则误报过高 → 停止迭代，先补规则与证据源。

## 七、首轮动作（MVP-001）

- **导师访谈**（3–5 名）：核对预审频率、最耗时环节、常见错误、证据要求、审批习惯；**引导回忆最近一次真实预审任务**，不提问泛化的"你会不会用 AI"。
- **评测集**：≥10 个公开 / 授权 / 明确合成的教学设计样例；每条 P0 规则 ≥3 正例 + 3 反例 + 1 边界/NA 例；含缺课标、错误字段、冲突规则、无来源资源、模型超时等污染样例。
- **标注**：由 ≥1 名导师标注关键风险与建议接受/修改/拒绝结果。
