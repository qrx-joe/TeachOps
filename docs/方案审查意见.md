# 《GOAI 初赛分步骤执行方案》审查意见

> 审查日期：2026-08-14
> 审查对象：`docs/GOAI_初赛分步骤执行方案.md`（V1.0）
> 结论：**方案可执行，批准实施**。时间预算各阶段加总核对无误（19.25 小时），停止线、降级路径和"绝对不做清单"定义清楚。以下 5 点为实施中的补充修正，不改变原方案框架。

## 1. 总体评价

方案的最强之处是把"完成"定义为可核验的提交状态而不是功能数量：

- 完成标准逐条可检查（字数、可打开、角色不互相替代、证据类型标注）。
- 每个高风险步骤都有时间上限和停止条件，AgentTeams 失败不拖累必交材料。
- 用户与 AI 助手的职责切分明确，API Key 全程不经过聊天和仓库。
- "绝对不做清单"直接对应初赛评分权重（场景、协作、Skill 三项占 75%），不做无效工程。

## 2. 实施修正与补充

### 2.1 步骤 0 是用户侧硬阻塞，材料工作应并行推进（修正）

方案将步骤 0 排在最前，但登录参赛系统只能由用户完成。若串行等待，步骤 1-6 会被白白推迟。

处理：AI 助手先行完成步骤 1-6 的材料（简介按"含标点 ≤500 字"的保守口径控制），用户核对官方规则后，只需回填 `submission/提交要求核对表.md` 并触发一次复核（字数、格式、命名）。若官方规则与本方案冲突，以官网为准调整材料，此时改动量很小。

### 2.2 缺一个"正常流程 fixture"兜底（补充）

步骤 10 只为**缺证据异常流程**准备了 fixture replay 降级。若步骤 7 烟雾测试失败，正常流程同样没有任何可展示的产物，PPT 第 4 页（端到端闭环）将只有设计图。

处理：为 `normal-case` 一并预置 expected-output（evidence_packet.json / revision.md / audit_report.json / review_decision.md），统一标注 `fixture replay`。这样无论 AgentTeams 是否跑通，两条流程都有材料可讲，且真实运行成功后可直接替换为 live 证据。

### 2.3 步骤 9 建议增加轮次上限（补充）

正常流程 2 小时时间盒内，多 Agent 多轮往返加模型延迟，可能出现"流程对了、文案不满意"的反复重跑。方案有"不追求更好文案"的停止条件，但没有量化。

处理：一次完整正常流程最多尝试 2 轮。第 1 轮失败可修复后重跑 1 次；第 2 轮结束即冻结当时产物（哪怕是部分产物），转入步骤 10。文案质量问题记入复赛清单。

### 2.4 PDF 导出路径需提前确认（补充）

本机无 LibreOffice。PDF 导出依赖 PowerPoint（本机是否安装待确认）或赛后另行导出。若两者都不可用，初赛提交 PPTX（官方要求"PPT 或 PDF"二选一即可），不为此引入新的安装排障。

### 2.5 版本控制策略（补充，用户已确认）

方案未写明 git 策略。按用户要求执行：每个步骤完成即提交一次；`.gitignore` 先于首个业务提交落库，隔离密钥、提交回执（含个人信息）、官方模板（版权）与内部规格 docx；公开仓库保持最小结构。

## 3. 风险核对

方案第 6 节风险表覆盖了主要风险，逐条核对后无遗漏项需要新增。补充一点观察：截图中个人信息的把关（用户名、头像、路径中的真实姓名）在步骤 12/13 的检查清单中已有对应项，执行时按清单逐项过即可。
